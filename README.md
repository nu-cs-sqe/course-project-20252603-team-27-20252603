### Mutation Testing Analysis and Equivalent Mutants
#### Game.java:
- Line 390 in Game.java can't be killed since if to.getCol() = from.getCol(), the methods will return false before this line. This line is used to determine which direction the king goes

#### Piece.java:
1) Rook Movement Directionality Check (Arithmetic Mutant) 
   - Target Line: int colDiff = to.getCol() - from.getCol(); inside isValidRookMove(...)
   - Mutation Type: Arithmetic Substitution (PITest inverted the subtraction order or substituted an absolute difference/inline constant). 
   - Justification of Equivalence: The value calculated in colDiff is consumed immediately below it exclusively within a boolean evaluation: `boolean isStraightLine = (rowDiff != 0 && colDiff == 0) || (colDiff != 0 && rowDiff == 0);` This conditional logic exclusively evaluates whether colDiff is exactly zero or non-zero, completely discarding the mathematical sign and the step's exact magnitude. Consequently, if a mutation flips the subtraction order and changes a value like 4 to -4, the check still evaluates -4 != 0 as true and routes the logic identically. Because any non-zero value satisfies the condition exactly like the original calculation, the program behavior remains untouched, rendering the mutant completely equivalent.
2) Diagonal Path Obstruction Indexing (Arithmetic Mutant)
   - Target Line: new Location(from.getRow() + i * rowStep, from.getCol() + i * colStep)
   - Mutation Type: Arithmetic Substitution (PITest replaced the multiplications with additions, or changed the mathematical signs).
   - Justification of Equivalence: This loop scans the intermediate squares of a diagonal trajectory to check for blocking pieces. Because rowStep and colStep are generated by Integer.compare(), their values are restricted entirely to a baseline of 1 or -1 during any true diagonal movement. Mathematically, multiplying any loop index i by 1 or -1 yields an identical numerical value to adding or subtracting i directly. Because the resulting coordinate lookups remain entirely unchanged across all valid diagonal vectors, the branch execution matches the original code exactly, proving the mutant is equivalent.
